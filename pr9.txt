fix(tui): normalize line endings to \r\n and preserve terminal onlcr to fix staircase effect

## Summary
Fixes the terminal "staircase effect" when launching the interactive Terminal UI (`gh-stats tui`) where lines failed to return to the left margin.

## Root Cause
When entering terminal raw mode via `stty raw`, POSIX terminals disable output post-processing (`OPOST` / `ONLCR`). In that mode, standard line feed (`\n`) only moves the cursor down one row without returning the cursor to column 0, causing each subsequent line to indent from where the previous line finished.

## Key Changes
- **Explicit Carriage Returns (`pkg/tui/tui.go`):**
Normalized all rendered screen buffer lines to emit explicit `\r\n` line endings (`CR+LF`) before writing to `stdout`:
```go
viewBuffer = strings.ReplaceAll(viewBuffer, "\r\n", "\n")
viewBuffer = strings.ReplaceAll(viewBuffer, "\n", "\r\n")
```
Appended `\r\n` upon dashboard exit to restore the shell prompt cleanly to column 0.

- **Preserve Output Processing (`pkg/tui/terminal.go`):**
Switched raw mode configuration from `stty raw -echo min 1` to `stty -echo -icanon min 1` (non-canonical character input with echo disabled), which keeps `ONLCR` (automatic mapping of newline to carriage return) enabled in the terminal driver.
